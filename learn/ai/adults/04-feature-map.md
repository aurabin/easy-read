# Lesson 4: The feature map

**Time:** 12 minutes. **You need:** lesson 3.

## Short answer

A feature is a capability. A map is not a guarantee.
The project now lists AI features and standard development features.
Each row has a meaning, a small task, and a status.

## The two lists

- [`features/ai-features.md`](../features/ai-features.md): models, prompts,
  agents, tools, language, media, safety, operations.
- [`features/dev-features.md`](../features/dev-features.md): workspace, source
  control, environment, build, quality, delivery, operations, security,
  accessibility, data, documentation.

## The status keys

- **here** — usable in this folder today.
- **taught** — explained in a lesson, with a task.
- **planned** — named, not built.

Do not turn "planned" into "available" in a talk or a sales page.

## A coverage audit

Pick one category. Read every row.
Mark each row with one of three words:

1. Works.
2. Taught.
3. Missing.

Then pick the smallest missing piece.
Build that, not the whole list.

## The lifecycle

The map covers a full path:

1. Revise one change.
2. Debug the failure.
3. Remove garbage.
4. Clean the workspace.
5. Build the artifact.
6. Test across environments.
7. Maintain the result.
8. Publish it.
9. Charge for it, if you choose.

Lessons 5 to 8 teach that path.

## Try this

Choose one category from each list.
Mark all rows as works, taught, or missing.
Name one gap you can close in 30 minutes.

## Ask me

Ask the agent: "Audit one category and name the smallest useful gap."
