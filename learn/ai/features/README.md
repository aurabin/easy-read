## How to read a row

Each feature row has four parts:

- **Feature** — the name.
- **What it means** — a short explanation.
- **Try this** — one small task.
- **Status** — `here`, `taught`, or `planned`.

The status keys:

- **here** — you can use it in this project today.
- **taught** — a lesson explains it and gives you a task.
- **planned** — named here, not built yet.

## The lifecycle

The map follows one path:

1. Revise one change.
2. Debug the failure.
3. Remove garbage.
4. Clean the workspace.
5. Build the artifact.
6. Test across environments.
7. Maintain the result.
8. Publish it.
9. Charge for it, if you choose.

## How to use the map

1. Pick one feature. Not ten.
2. Read its row.
3. Do the smallest task in the "Try this" column.
4. Write one line about what happened.
5. Ask the agent one question about it.

Then pick the next feature.

## The honest limit

This map names features. It does not prove that this project has them all.
Only the rows marked **here** work in this folder today.
The rest are lessons or plans.

No list can be truly complete. Tools change fast.
If a feature is missing, add it. Keep the status honest.
