# Lektion 24 — Mitmachen

## Die Idee

Ein offenes Projekt lebt von vielen Menschen.
Du musst kein Profi sein.
Ein Satz kann schon helfen.
Alles geht schriftlich.

## Drei Wege

### 1. Fehler melden

Du siehst etwas, das nicht stimmt.
Schreib ein Issue auf GitHub.
Sag was du gesehen hast.
Sag was du erwartet hast.
Sag auf welcher Seite es war.

### 2. Text verbessern

Mach einen Satz kürzer.
Erklär ein hartes Wort.
Schick eine Übersetzung.
Schreib eine neue Lektion.

Regeln:
- höchstens zwölf Wörter pro Satz,
- ein Gedanke pro Absatz,
- keine Belehrung, kein Spott.

### 3. Code oder Bild

Bau eine kleine Demo.
Zeichne ein Bild.
Schreib ein Programm für KolibriOS.
Ergänze eine Prüfung.

## Der Prüfer

Nach jeder Änderung:

```sh
node tools/self-engineer.mjs
```

Er muss „OK" sagen.
Dann ist dein Beitrag sauber.

## Ein Pull Request

1. Forke das Repository.
2. Mach einen Branch.
3. Mach einen Commit.
4. Öffne einen Pull Request.

Oder schreib einfach ein Issue.
Das reicht auch.

## Ehrlich

Das Projekt ist nicht mit echten Nutzern getestet.
Du gehörst vielleicht zu dieser Gruppe.
Dann zählt deine Meinung zuerst.
Schreib uns. Kein Video, kein Anruf.
